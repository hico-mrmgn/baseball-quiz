# つぎ、どうする？ - 野球の判断力トレーニング

野球の試合状況を読み取り、最適なプレーを選ぶ判断力トレーニングアプリです。

対象は学童・少年野球。ただし言葉づかいだけを小学生向けにし、**問う判断のレベルは
ジュニア選抜（ファイジュニ）のセレクションで見られる水準**に置いています。

## 画面の構成

トップ画面の主導線は「今日のトレーニング」一つです。それ以外は
「選んで練習」「基本練習」「解説編」の3つに畳んでいます。

```
今日のトレーニング   実戦5場面 → 守り切れ1回 → 結果（弱かった判断から直接練習へ）
選んで練習           実戦シナリオ（判断の種類別）／ 守り切れ（イニング別）
基本練習             ポジション別クイズ・難易度でしぼる
解説編               守備フォーメーションの図解
```

以前は「何かを始める」入口がトップに28個あり、スマホでは2.2画面ぶんの高さが
ありました。実戦トレーニングと基礎ドリルがそれぞれ独立した習慣ループを持っていて
（デイリーも苦手リストも基礎ドリル側だけにあった）、どちらをやればいいのかが
画面から読み取れない状態でした。習慣ループを実戦シナリオ側に寄せたうえで、
入口を4つに整理しています。

| | 対応前 | 現在 |
|---|---|---|
| トップの入口数 | 28 | 4 |
| トップの高さ（390px幅） | 1882px（2.2画面） | 844px（1.0画面） |
| トップのボタン総数 | 36 | 6 |
| メインモードの復習ループ | なし | タグ単位で成立 |

## それぞれのトレーニング

### 🧠 実戦トレーニング（メイン）

点差・イニング・カウント・走者の脚まで込みの場面で判断させるモード。
「型を覚えているか」ではなく「点差とアウトカウントで型を捨てられるか」を問います。

- **双子問題** … 打球はまったく同じで、点差・アウトカウント・走者の配置・守備隊形だけが
  違う2問を連続で出題します（16ペア）。「1アウト三塁のサードゴロ」の正解は、5点リードなら
  一塁、1点リードの最終回なら本塁。同じ場面で答えが変わる理由を体で覚えるための仕組みです。
- **配点制** … 正解は1つだけではありません。選択肢ごとに
  `最善手 +3 / まあOK +1 / もったいない 0 / 試合が壊れる -1` の配点を持ち、
  「間違ってはいないが物足りない判断」と「試合を壊す判断」を区別します。
- **選択肢ごとのフィードバック** … 回答後は選んだ選択肢だけでなく、**4つすべて**について
  「なぜその点数なのか」を表示します。
- **選択肢のシャッフル** … 出題のたびに並び順を混ぜます。並び順のクセで解けないようにするためです。
- **タグ別の弱点分析** … 結果画面で「点差判断」「カバーリング」「走者の脚を読む」など、
  判断の種類ごとの成績を出します。

出題は判断の種類でも絞り込めます（全部／守備の判断／攻撃の判断／点差で変わる判断／投球前の準備）。

### 🔥 今日のトレーニング（毎日の主導線）

実戦5場面 → 守り切れ1回 をひと続きのセッションとして進めます。

- 出題は日付シードで決まるので、同じ日に開き直しても中身は変わりません
  （気に入らない出題を引き直せてしまうと練習になりません）。
- そのうえで、**苦手な判断（タグ）を含む場面を優先して出します**。
  トップのボタンに「今日は〈点差判断〉を多めに」と表示されます。
- 終わったあとの結果画面から、弱かった判断だけを集めた練習に直接入れます。

苦手の記録は問題ID単位ではなく**判断の種類（タグ）単位**です。実戦シナリオは
53場面しかないため、ID単位ではすぐ一巡してしまい復習になりません。タグ単位なら
場面数が少なくても積み上がり、「何を練習すればいいか」も子どもに伝わります。

### 🛡️ 守り切れ！（イニング制）

1問1答ではなく、**1イニングを最後まで守り切れるか**を問うモード（5イニング）。
打者一人につき1場面で、判断の良し悪しがそのまま失点になります。
追いつかれた時点で失敗、打者を抑え切ればクリア。

実戦の守備は「1つのプレーの正解」ではなく「3アウトを取り切るまで失点を止め続けられるか」で
評価される、という考え方をそのままゲームにしています。

### ✏️ 基本練習（基礎ドリル）

1170問のポジション別クイズ。基礎の型を固めるドリルです。
実戦トレーニングが「型を捨てる練習」なのに対し、こちらは「型を覚える練習」です。

- **選択肢のシャッフル** … 出題のたびに並び順を混ぜます。デイリーチャレンジだけは
  全員が同じ並びで解けるよう、日付シードから並びを再現します。
- **難易度でしぼる** … 初級 / 中級 / 上級 / プロ級。その難易度の問題がないテーマは選べません。

## その他の機能

- **解説編** … 守備フォーメーションの図解
- **レベル / デイリーチャレンジ / 間違えた問題** … LocalStorageで継続を支援
- **バッジ** … 20個を5つに分けています（続ける／判断の質／守り切れ／判断の種類／基本練習）。
  実戦シナリオの指標（最善手率・致命傷ゼロ・最善手の連続・タグの習熟）で評価します。
- **戦績** … 履歴・通算成績の表示

## データ構造

実戦シナリオは、状況を文字列ではなく構造化データで持ちます。
文字列だと点差もカウントも表現できず、「この場面の最善手」が1つに固定されてしまうためです。

```js
{
  id: 'sc-third-01b',
  theme: 'third',
  pairId: 'tw-third-01',           // 同じ pairId の2問が双子問題
  pairRole: 'b',
  tags: ['点差判断', '守備隊形を読む'],
  phase: 'post',                    // 'pre' = 投球前 / 'post' = 打球後
  sit: {
    inning: 7, half: 'bottom',
    side: 'defense',                // 'defense' = 守備側 / 'offense' = 攻撃側
    score: { us: 3, them: 2 },
    outs: 1,
    runners: { first: null, second: null, third: 'normal' },  // 'fast' | 'normal' | 'slow'
    count: { b: 1, s: 1 },
    batter: { hand: 'R', order: 5, trait: '長打力あり' },
    defense: '前進守備',
    play: 'サード正面へのゴロ',
    ballArea: 'third',
    note: 'この回を抑えれば勝ち。',
  },
  question: '...',
  choices: [{ text: '...', score: 3, fb: 'なぜこの点数なのか' }, ...],
  explain: { why: '...', key: '覚えること', drill: '練習メニュー' },
}
```

### 状況の見せ方

判断を決めるのは **点差・アウトカウント・走者** の3つです。これが変わると正解が
変わります。この3つだけを1行にまとめ、アウトは ●○○、走者は小さなダイヤ図で
出します。文字で書くより速く読めるためです。

以前はここに11個のタグを並べていましたが、そのうち7個（回・点差・アウト・
カウント・走者・守備隊形）は **となりのフィールド図が同じことを描いていました**。
絵で分かったことを文字でもう一度読まされると、そこは読み飛ばす場所だと
学習されてしまいます。回とカウントは図のスコアボードに任せました。

守備隊形は「定位置」のときは出しません。初期配置は判断の材料にならないためです
（53場面のうち33場面が定位置）。前進守備やバントシフトのように、チームの意思が
出ているときだけ表示します。

打者の特徴だけは図に描けないので、1行下に残しています。

守り切れ（イニング制）は打者をまたいで残るスコアボードを別に持っているので、
`hasScoreboard` を渡して点差とアウトを省きます。同じ数字を1画面に3回
出さないためです。

### フィールド図

守備位置と守備隊形のずらしは `src/data/fieldCoords.js` が持ちます。以前は同じ
座標が `ScenarioField` / `FieldDiagram` / `formations.js` の3か所に写してあり、
直すと必ずどこかが取り残される状態でした。

**y が大きいほどホーム寄り**です。前に出る隊形は `dy` を **+**、下がる隊形は
**−** にします。以前ここが逆で、「前進守備」「バントシフト」「定位置より少し前」の
3種類が後ろに下がって描かれていました。隊形が出てくる19場面のうち14場面が逆、
4場面は隊形名が図に登録されておらず何も動いていませんでした。解説が
「前進守備は1点もやらないというチームの約束」と書いている横で、図は逆を
描いていたことになります。

定位置そのものも実際の守備位置に寄せました。二塁手・遊撃手がベースラインの
真上に立っていて（一二塁間の中点 (139,98) に対し 2B が (138,96)）、
一塁手・三塁手はベースより手前でした。つまり定位置がすでに前進守備の深さまで
来ていて、前へ出す余白が残っていなかったのが逆向きの原因です。

`npm run audit:field` が、隊形名が図に登録されているか、前へ出る隊形が本当に
前に描かれているかを失敗扱いで止めます。向きの間違いは目で見ないと気づけないので、
機械で見ます。

選手は捕手（しゃがんでミットを構える）・投手（プレートを踏む）・野手（グラブを持つ）を
描き分けています。守備は「誰がどこで何をしているか」を読む絵なので、9人が同じ形だと
読み取れません。

### 立場（守備側／攻撃側）

実戦シナリオは守備38場面・攻撃15場面が混ざっていて、今日のトレーニングは
テーマをまたいで5場面を引きます。つまり画面は守り→攻め→守りと切りかわります。

以前この立場は問題文の中でしか伝えておらず、書き方も揃っていませんでした。

- 「**サードは**正面でしっかり捕った。どこへ投げる？」
- 「**自分は二塁ランナー。**2アウトでレフト前ヒット。どうする？」
- 「**ライトは**ダイビングすれば届くかもしれない。どうする？」

`sit.side` は最初からデータに入っていたのに、画面に出していませんでした。
いまは状況パネルのいちばん先頭に出します。ここが読めていないと、点差も
アウトカウントも使いようがないためです。守り切れ（イニング制）は常に守備側です。

`npm run audit:viewpoint` が、`sit.side` の欠損とテーマとの食い違いを
失敗扱いで止めます。

## 文章の書き方

対象が学童のため、**小学校で習う漢字（教育漢字）は開かずに漢字で書きます**。
中学以上で習う漢字を含む語は、交ぜ書きになるのを避けてかなのまま残します。

| かなのまま | 理由 |
|---|---|
| ふつう | 普＝中学 |
| ちがう / もどる | 違・戻＝中学 |
| 切りかえる | 替＝中学（切は漢字のまま） |
| おそい | 遅＝中学 |
| そろえる | 揃＝常用漢字表外 |

とき・こと・もの・ため・ほう などの形式名詞は、一般的な表記ルールどおり
かなで書きます。

## 出題データの品質

問題は「正解が分かること」ではなく「中身を読まなくても当たってしまうこと」。
基礎ドリルにはその抜け道が2つありましたが、いずれも解消済みです。

| 指標 | 対応前 | 現在 |
|---|---|---|
| 正解インデックスの最大シェア | 62.8%（走塁編は93%が0番目） | 出題時にシャッフルするため実プレーには出ない |
| 「一番長い選択肢を選ぶ」期待正答率 | 69.0% | **44.0%**（偶然なら25%） |
| 正解が2位より20文字以上長い問題 | 92問 | **0問** |
| 正解が2位より10文字以上長い問題 | 315問 | **0問** |
| `difficulty` の利用 | 表示専用 | 出題のフィルタに使用 |

長さの偏りは、誤答が「何もしない」「ランナーに任せる」のような短いスタブで、正解だけが
具体的に長い、という形が原因でした。誤答を具体的で同程度の長さに書き直し、正解からは
冗長な説明を削って解説側に寄せています（404問をリライト）。

`npm run audit:questions` でこれらの指標を計測でき、閾値を超えると失敗します。
問題を追加・編集したら実行してください。

## 解説と正解の食い違い

問題の中身の誤りは、選択肢の長さの偏りより学習への害が直接的なので、別の監査に
分けています（`npm run audit:explanations`）。見ているのは3つです。

1. **並び順に依存した選択肢**（失敗扱い）… 「BとCは同じ意味」のように他の選択肢を
   ラベルで指すもの。出題時にシャッフルするため意味が壊れます。
2. **解説が正解を打ち消している**（失敗扱い）… 「フォースではない」と書いてあるのに
   正解が「フォースアウト」など、野球でよくある食い違いをパターンで持っています。
   解説が例外を補足しているだけの場合は誤検出になるので、除外条件も持たせています。
3. **解説が誤答のほうをよく説明している**（警告）… 文字のバイグラムの一致度で測ります。
   解説は「なぜ誤答がダメか」に触れることが多く誤検出が出るため、警告どまりです。
   引っかかった問題を人が読んで確認したら `REVIEWED_WARNINGS` に入れます。以降は
   「確認ずみ」として数え、**新規**として出るのは未確認のものだけになります。
   問題の中身を書きかえたら一覧から外して読みなおしてください。

この監査で見つけて直した誤り:

| 問題 | 内容 |
|---|---|
| `third-004` | 一・三塁のサードゴロで「三塁を踏んでフォースアウト」が正解になっていた。二塁が空いているのでフォースは成立せず、解説も存在しない「2塁ランナー」を指していた |
| `batting-085` | 1アウト一塁の外野フライで「動かずに1塁で待つ」が正解になっていた。正しいハーフウェイが選択肢にすらなかった |
| `rules-043` `rules-055` | 「BとCは同じ意味」という選択肢。シャッフル導入で意味が壊れていた |
| `pitcher-056` `pitcher-073` `pitcher-085` | ボークになる場面なのに正解が「ボークになる可能性が高い」で、誤答に「審判次第」が並んでいた。ルール上は確定してボークなので「ボークになる」に直した |

### 残っている課題

- 基本練習に、ポジション別のテーマなのに走者の判断を聞いている問題が8問
  あります（`outfield-062` など、外野編で「三塁ランナーはいつスタートを
  切るか」を聞くもの）。野球としては正しいのですが、外野編で学ぶ価値があるのは
  「タッチアップされる場面で外野手はどこへ、いつ投げるか」のほうです。
  直すには問い自体を作りなおすことになるので、`audit:viewpoint` の
  `KNOWN_MISMATCH` に既知として置き、新しく増えたものだけが出るようにしています。
